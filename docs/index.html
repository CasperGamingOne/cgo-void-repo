⚡ Quick Installation

1 Import Public Verification Key
Download and trust the repository RSA signing key in your system's XBPS keyrings:
sudo wget -O /var/db/xbps/keys/cgo-void-repo.pem https://caspergamingone.github.io/cgo-void-repo/cgo-void-repo.pem
2 Choose Your Repository Channel
Select the architecture variant suitable for your processor:
🚀 Best Performance: Compiled with -march=x86-64-v3 -O3 -pipe (AVX2, FMA, BMI1/2). Ideal for Intel Haswell (2013+) and AMD Zen (2017+) or newer. Self-contained channel with all packages. 
echo "repository=https://github.com/CasperGamingOne/cgo-void-repo/releases/download/rolling-v3" | sudo tee /etc/xbps.d/10-cgo-void-repo.conf
📦 Maximum Compatibility: Standard baseline 64-bit compilation. Runs safely on any 64-bit x86 hardware, hypervisors, and legacy PCs. Self-contained channel with all packages. 
echo "repository=https://github.com/CasperGamingOne/cgo-void-repo/releases/download/rolling" | sudo tee /etc/xbps.d/10-cgo-void-repo.conf
3 Synchronize & Install
Synchronize package indexes and install packages with native clean names:
sudo xbps-install -S
sudo xbps-install -S noctalia umbriel vmware-workstation megasync

🔍 Check Your CPU Microarchitecture

Wondering if your CPU supports the x86_64-v3 channel? Run this single command in your Void Linux terminal to verify your dynamic linker capabilities: 

/lib/ld-linux-x86-64.so.2 --help | grep -E "x86-64-v[234]"
x86-64-v3 (supported, searched) Your CPU supports AVX2, FMA, BMI1/2. Use the rolling-v3 channel!
Only x86-64 or x86-64-v2 Your CPU is baseline/legacy or running in a VM without AVX2. Use the rolling channel!

⚖️ Packaging Guidelines & Licensing Compliance

📜 License Integrity

Every package explicitly follows upstream license agreements. Free software (MIT) installs complete license files to /usr/share/licenses/ via vlicense. Proprietary software (VMware, Google Antigravity, MegaSync) includes official EULAs and is marked with Void's restricted=yes flag.

🐧 Void Linux Packaging Standards

All templates are linted with xlint (0 warnings). Packages strictly isolate hostmakedepends, makedepends, and runtime depends. Native Runit service scripts are placed in /etc/sv/, and kernel modules are managed cleanly via official DKMS triggers without modifying root partitions.

🔐 Cryptographic Verification

Every .xbps package and repository index (x86_64-repodata) is cryptographically signed using our 4096-bit RSA signing key. Your system verifies signatures locally before installing any package.
